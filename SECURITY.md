# Security Policy

## Supported versions

The project is in early development; the default branch is currently the supported version. This table will be updated when releases exist.

## Reporting

Do not open a public issue for a suspected vulnerability. Use GitHub private vulnerability reporting for this repository when available. Include impact, affected commit/file, minimal reproduction without credentials, and suggested mitigation.

If private reporting is unavailable, contact the repository owner through the private method configured on the GitHub profile. Never send tokens, private keys, or full confidential reports.

## Scope

Report issues in code, packaging, CI, dependency handling, credential management, or documentation that could cause unauthorized access, disclosure, unsafe execution, or misleading results. Report upstream GitHub or dependency issues to the relevant provider too.

## Process

The maintainer will triage, assess affected versions, and coordinate a fix when practical. No fixed response time or bounty is promised. Coordinate privately before disclosure.

## Safe harbor

Test only systems and repositories you own or are explicitly authorized to assess. Do not exfiltrate secrets, degrade availability, access unrelated data, or bypass controls. Stop and report immediately if real credentials or personal data are encountered.
